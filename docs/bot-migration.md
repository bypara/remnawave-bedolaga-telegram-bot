# Режим переезда бота

По умолчанию выключен. Это заглушка входящих действий, а не переключатель
инфраструктуры: домены, база, платежи и фоновые задачи не меняются.

В админке бота: «Настройки бота» → группа обслуживания → категория
«🚚 Переезд бота». В кабинете — та же категория системных настроек.

1. Задать `BOT_MIGRATION_URL`: `https://t.me/new_service_bot` или ссылку
   с `?start=campaign_code`. Новый бот уже должен работать.
2. Задать `BOT_MIGRATION_MESSAGE` (обычный текст, не HTML/Markdown) и
   `BOT_MIGRATION_BUTTON_TEXT`.
3. Включить `BOT_MIGRATION_ENABLED`. Действует сразу, без перезапуска.
4. Для отмены выключить `BOT_MIGRATION_ENABLED`.

Настройки сохраняются в `system_settings`. Миграция 0132 добавляет таблицу
персональных ссылок/начислений `bot_migration_claims`; применяется при обновлении
бота. Переменные `.env` с такими же именами имеют приоритет над админкой.

## Бонус за переход

1. Задать `BOT_MIGRATION_BONUS_AMOUNT_RUBLES` в рублях (например `75.50`).
2. Включить `BOT_MIGRATION_BONUS_ENABLED`.
3. В текстах `BOT_MIGRATION_MESSAGE`, `BOT_MIGRATION_BUTTON_TEXT` и
   `BOT_MIGRATION_BONUS_SUCCESS_MESSAGE` можно использовать `{bonus}`.
   Например: «Перейти и получить {bonus} ₽».

Старый бот выдаёт персональный `?start=move_...` зарегистрированному активному
пользователю. Он заменяет рекламный start-код из настроенного URL. Сам клик
не виден боту: деньги начисляются после `/start` в новом боте по этой ссылке.
Оба бота должны использовать одну БД и эту версию кода.

Токен связан с аккаунтом; пересылка ссылки не даёт бонус другому человеку.
Начисление, история с методом `manual` и отметка получения сохраняются одной
транзакцией. Повторный запуск, смена суммы и переключение режима не дают бонус
повторно. Кампании и реферер пользователя не изменяются.

Уже выданная ссылка сохраняет обещанную сумму. Новая сумма действует для
пользователей, которым ссылка ещё не выдавалась. Изменение целевого бота
перевыпускает невостребованную ссылку при следующем обращении к старому боту.
Старый токен перестаёт работать; уже начисленный бонус не сбрасывается.

Для уже получивших бонус и не подходящих аккаунтов используются изменяемые
`BOT_MIGRATION_NO_BONUS_MESSAGE` и `BOT_MIGRATION_NO_BONUS_BUTTON_TEXT`.
При отключённом бонусе работает обычная настроенная ссылка.

## Что перехватывается

- Личные сообщения, команды, `/start` с любым payload.
- Callback-кнопки, включая старые/неизвестные и кнопки в inline-сообщениях.
- Активные пользовательские FSM-диалоги: их обработчики не вызываются.

Администраторы из `ADMIN_IDS` сохраняют обычный доступ. Сообщения в группах
не заменяются заглушкой. URL/WebApp-кнопки уже отправленных сообщений открываются
самим Telegram и не могут быть перехвачены middleware.

Бот, чьё подтверждённое Telegram-имя совпадает с именем из целевой ссылки,
не показывает заглушку: новый бот остаётся рабочим даже с общими настройками БД.
На нём сохраняются обычные проверки доступа и обязательных каналов. При проходе
канальной проверки код переезда хранится отдельно от рекламной атрибуции в FSM.

`successful_payment` и `pre_checkout_query` не перехватываются режимом переезда.
Внешние платёжные вебхуки тоже продолжают работать. Старые счета нужно учитывать
при переключении полноценного сервиса на нового бота.

## Важно для будущего переезда

- Ссылки рекламных кампаний не используются для бонуса переезда: у него отдельный
  персональный сценарий для существующих пользователей.
- Не запускайте два полноценных сервиса с автопродлением/мониторингом на одной БД.
  После переноса старому боту нужен отдельный лёгкий процесс-заглушка без фоновых
  задач. Этот режим сам такие задачи не выключает.
- Старые ссылки на подарки/рефералов не пересылают payload автоматически: сейчас
  кнопка использует ссылку перехода/персональный код переезда. Для их сохранения нужен отдельный
  сценарий совместимости перед реальным переключением.
- Кабинет можно перенаправлять `app.huntcdn.com` → `web.censet.net`, сохранив путь
  и query string. Не применяйте общий редирект к API/платёжным webhook-маршрутам.
  Подписочный домен лучше сохранить как работающий совместимый адрес.

## Новые домены

- `web.censet.net` — кабинет (включая same-origin `/api`).
- `sub.censet.net` — подписочные ссылки, без смены ключей/путей пользователей.
- `hooks.censet.net` — Telegram, RemnaWave и платёжные вебхуки.
- `censet.net`/`www.censet.net` — необязательны, для сайта/страницы перехода.

Отдельный `api.censet.net` текущей архитектуре не нужен. Панель RemnaWave может
остаться на прежнем служебном домене. Старые домены `app/sub/hooks.huntcdn.com`
сохраняются для совместимости; общим редиректом вебхуки не закрываются.
